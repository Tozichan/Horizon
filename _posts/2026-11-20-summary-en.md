### [PHP 流包装器将混合大小写 HTTPS 静默降级为明文](https://x.com/ljachowicz/status/2123477025268924514) ⭐️ 8.0/10

PHP 的 HTTP 和 FTP 流包装器在匹配 scheme 时不区分大小写，但只有在第五个字符为小写“s”时才启用 TLS，因此像 httpS:// 或 FTPS:// 这样的 URL 会以明文 HTTP/FTP 发送，暴露令牌、Basic 认证凭据、Cookie、POST 请求体和 FTP 登录信息，包括在第三方重定向之后。该问题被追踪为 CVE-2026-128064（GHSA-f6gg-rchx-xw8j），CVSS 4.0 评分为 8.2，并已在 PHP 8.2.36、8.3.37、8.4.28、8.5.13 和 8.6.0 中修复。PHP 8.1 及更早版本已停止支持（EOL），不会获得补丁；这些版本的用户必须自行将 URL scheme 规范化为小写。该报告来自一条社交媒体帖子，而非主要安全公告。

telegram · zaihuapd · Nov 20, 03:04

**「Background」** PHP&\#x27;s HTTP and FTP stream wrappers are the built-in handlers behind functions such as file\_get\_contents\(\) and fopen\(\) when a URL is passed, so they underpin many common outbound HTTP and FTP requests in PHP applications. The flaw stems from a mismatch inside those wrappers: the scheme is recognized case-insensitively, but TLS is enabled only when a lowercase &quot;s&quot; appears at a fixed position, so mixed-case schemes fall through to plaintext.

**「影响」** 运行 PHP 8.1 或更早版本的用户无法获得上游修复，必须自行将 URL scheme 规范化为小写，或升级到已修复版本。在已修复版本上，任何接受用户提供或重定向 URL 的代码都应验证 scheme 是否被正确解析，因为该缺陷仅在特定大小写模式下才会显现。
